# 架构

## 分层

```
packages/core         内核：加密、分块、引擎、原生日志、后端
packages/dsh-plugin   DSH / dsh-go 插件：原生界面 + 定时同步 + 工具 + 命令
packages/mcp-server   MCP 总线：给 Codex 等智能体的六个工具
packages/cli          命令行：初始化、校验、导出、导入
```

`core` 不发布到 npm，而是由 `scripts/vendor-core.mjs` 复制进每个要发行的包里，所以每个包都是自包含的、可以单独安装。这是刻意的：手机上 `pnpm add` 一个目录就能跑，不需要先装四个包。

## 数据流

```
DSH 事件 ──portableFromDshEvent──▶ 记录 {id, origin, role, text, tool}
                                        │
                     ┌──────────────────┴──────────────────┐
                     ▼                                     ▼
              data/<会话>/<设备>/…jsonl.enc          native/<会话>/<设备>/…zst.enc
              （给面板、MCP、镜像读）                （给另一台 DSH 导入）
```

**为什么两条线都要**：前者是跨智能体可读的通用格式；后者是 DSH 的原始日志，只有在它上面 DSH 才能校验并继续对话。只保留前者会丢掉工具调用语义，只保留后者则别的智能体读不了。

## 关键不变量

1. **路径所有权**：`data/<会话>/<设备>/` 和 `native/<会话>/<设备>/` 只由该设备写。所以 Git 合并永远按路径合并，不会在同名文件上冲突。
2. **序号稠密**：合并时按 `seq` 去重排序，读出来必须是 `0..n-1`。测试会断言这一点。
3. **导入不覆盖**：本机已有同 id 会话时，导入直接跳过并报告 `exists`。
4. **回声抑制**：设备 B 导入的会话，其前缀属于 A；B 只推自己新写的部分（`importedThroughSeq` 之后）。
5. **盐属于仓库**：新设备先拉取盐，再决定要不要创建；否则两台设备会派生两把钥匙。

## 一次同步做了什么

1. 列本地会话 → 读取每个会话的新事件 → 折成记录。
2. 按会话分块、加密、写入 `data/`；分块的序号区间写进文件名。
3. 把原生日志的**增量尾部**压缩、加密、写入 `native/`。
4. 提交并推送；被拒则 fetch + rebase 重试。
5. 拉取新块 → 解密 → 写镜像 → 对没见过的会话做原生导入。
6. 把导入的进度记进状态，供下一次的抑制逻辑使用。

## 失败时

- 解密失败：跳过该块、计数、继续。不中断整次同步。
- 推送失败：最多重试三次（rebase，失败再 merge），仍失败就把错误显示在面板。
- 引擎没有 `sessionQuery`：插件仍然加载，但只报告配置错误，不崩溃。

## 测试策略

| 层 | 方式 |
|---|---|
| 加密 | 往返、错口令、篡改、路径绑定、截断 |
| 转换 | 真实 DSH 事件形状、reasoning 不外发、图像只留引用 |
| 原生日志 | 与 DSH 实际写出的文件字节一致、多帧 zstd、cwd 本地化 |
| 引擎 | 双设备推拉、重复拉取不重复、密文无明文、损坏块跳过 |
| Git | 本地裸仓真实推拉、推送被拒后的恢复、令牌不泄漏 |
| 端到端 | 手机真机日志 → 仓库 → 第二台导入 → DSH codec 校验 |
| 续写 | 导入后继续写 → 只推增量 → 第三台合并去重 |

端到端用例读取的是仓库里那份真实手机日志的路径（`/root/.dsh/sessions/...`）。在 CI 上该路径不存在时用例会失败——这是刻意的：宁可让 CI 明确跳过一个真实环境用例，也不要让它悄悄变成空跑。
